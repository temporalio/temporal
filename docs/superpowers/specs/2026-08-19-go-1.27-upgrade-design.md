# Go 1.27 Upgrade Design

## Goal

Move both repository Go modules from Go 1.26.4 to Go 1.27.0 while preserving
existing runtime behavior and keeping the repository compatible with Go 1.27's
module, vet, and HTTP/2 changes.

## Changes

- Set the root and mixed-brain module directives to `go 1.27.0` and retain the
  deterministic `go mod tidy` output produced by Go 1.27.
- Change `UnprocessableTaskError.Error` to a pointer receiver. Its constructor
  already returns a pointer, and making the pointer the only error type satisfies
  Go 1.27's `%w` vet rule at every wrapping site without changing callers.
- Update the HTTP transport tests to verify HTTP/2 through the new public
  `http.Transport.Protocols` API. Preserve the TLS configuration cloning contract
  and its tests; Go 1.27 no longer exposes HTTP/2 setup by eagerly populating
  `TLSNextProto` and `tls.Config.NextProtos`.
- Leave golangci-lint at v2.9.0. No released version currently supports Go 1.27's
  export-data format, so a version bump would not make lint pass.

## Verification

- Run targeted tests for the queue error and HTTP transport changes with the Go
  1.27 toolchain.
- Run `make unit-test` with Go 1.27.
- Run `make lint-code` with Go 1.27 and record the known upstream golangci-lint
  export-data incompatibility in the draft PR until a compatible release exists.

## Risk

The code changes are compatibility migrations rather than new behavior. The main
temporary risk is that lint CI cannot run on Go 1.27 until golangci-lint publishes
support; the draft PR will make that blocker explicit.
